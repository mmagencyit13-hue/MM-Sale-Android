Mobile V666
1. Build/install the APK from the source ZIP using the included Android workflow. Keep the existing application package and signing configuration.
2. In Supabase SQL Editor, run backend/V666_BUDDY_MORNING.sql. This installs the Buddy-to-Firebase bridge and minute retry. It uses the existing report generator and existing mma-firebase-push Edge Function. If no morning reports are generated or the phone still gets no alerts, run backend/V666_BACKEND_CHECK.sql and review the scheduled job, generated reports and accepted Firebase jobs.
3. Biometric re-login: Enable Biometric Unlock in Account. Sign out and sign in with your current password once, then confirm the biometric setup prompt. The phone saves encrypted login credentials under an Android Keystore key that requires strong biometrics for each use. Re-login uses the existing employee login and device checks.
4. V666 corrects the mobile web 3-hour inactivity limit to 72 hours. A session rejected by Supabase still requires valid authentication. If a server-side 3-hour limit continues, inspect the authentication RPCs with the backend check.
5. Employee self-service password change requires a backend RPC that verifies the current password and updates the same password hash used by Desktop and APK. The backend check returns the relevant installed function definitions. It does not change passwords or expose stored password values.
